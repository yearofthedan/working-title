# Commits and merges

**Audience:** anyone landing a change here.
**Purpose:** what a change's messages look like, on the branch and in the log.

- **The issue number leads the subject** of a pull request title and of every commit: `15: Check claims against their docs`. Merges are the exception, since `Merge branch 'main' into …` has its own shape.
- **A change reaches `main` through a pull request, squash-merged**, so the pull request title is the message that lands. [The squash merge message](https://docs.github.com/en/pull-requests/reference/pull-request-merges#merge-message-for-a-squash-merge) is generated by GitHub and can be edited before it lands, and [the squash settings](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/configuring-pull-request-merges/configuring-commit-squashing-for-pull-requests) choose what the default message is. The commits on the branch are read in the pull request while it is reviewed, so they carry the issue number too.
- **An agent's commit on a story branch names its model** in an `Agent-Model:` trailer, written with [`git commit --trailer`](https://git-scm.com/docs/git-commit#Documentation/git-commit.txt---trailertokenvalue): `git commit -m '76: Refuse a commit without its model' --trailer 'Agent-Model: anthropic/claude-opus-5-5'`. A story branch is one whose name starts with its issue number, and the [`commit-msg` hook](../../scripts/commit-msg) refuses a commit on one without the trailer; merges pass. `git log --format='%(trailers:key=Agent-Model)'` reads them back ([pretty formats](https://git-scm.com/docs/pretty-formats#Documentation/pretty-formats.txt-trailersoption)). The builder's own commits skip the hook with `--no-verify`.
- **The pull request body names who wrote it**, each role with its model: the main session, the one that talks to the builder, with its tool; the execution agent, when one did the work; the pull request review; and any live reviewers. The body outlives the branch; the merge carries the title alone.
- **The repository settings carry part of it**: squash and rebase merging are allowed, merge commits are refused, and the squash message defaults to the pull request title — the setting that makes the title above the message that lands.
- **The ruleset on `main` carries the rest** ([the ruleset](https://github.com/yearofthedan/working-title/rules/24845766), [#16](https://github.com/yearofthedan/working-title/issues/16)): a pull request, squash only, the `check` job required by name, and code scanning results required from CodeQL. [A ruleset sets the merge types a branch accepts and the checks it waits for](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-rulesets/available-rules-for-rulesets), so squash is the only method `main` takes and the branch's commits never reach it as they are.
