# Internationalization (i18n) Guide

This project uses `vue-i18n` (v9) for managing all user-facing strings with a two-tier architecture.

## Architecture Overview

Our i18n system is split into two layers:

### 1. Static App Strings

Global UI elements, navigation, and common errors loaded at application startup.

**Location:** [`src/i18n/en.json`](../../src/i18n/en.json)

### 2. Template Strings

Strings specific to a writing methodology (e.g., Snowflake Method) loaded lazily when a project using that template is opened.

**Location:** `src/features/process-templates/{template}/locales/en.json`

**Why two-tier?** This architecture maintains feature isolation and optimizes bundle size by loading template-specific strings only when needed.

## Adding Static App Strings

### Step 1: Update Locale File

Add your key-value pair to [`src/i18n/en.json`](../../src/i18n/en.json):

```json
{
  "app": {
    "home": {
      "welcome": "Welcome to Working Title"
    }
  }
}
```

### Step 2: Update TypeScript Schema

**Critical:** Update [`src/i18n/types.ts`](../../src/i18n/types.ts) to match the JSON structure:

```typescript
export interface MessageSchema {
  app: {
    home: {
      welcome: string
    }
  }
  // ...
}
```

This provides autocomplete and type safety in components.

### Step 3: Use in Components

```vue
<script setup lang="ts">
import { useI18n } from 'vue-i18n'
const { t } = useI18n()
</script>

<template>
  <h1>{{ t('app.home.welcome') }}</h1>
</template>
```

## Adding Template Strings

Template strings follow the same pattern but live in the template's directory.

### Step 1: Update Template Locale

Add to `src/features/process-templates/snowflake/locales/en.json`:

```json
{
  "template": {
    "step": {
      "summary": {
        "label": "One-Sentence Summary",
        "instruction": "Describe your story in one sentence..."
      }
    }
  }
}
```

**Important:** All template strings must be under the `template.*` namespace.

### Step 2: Use in Components

```vue
<template>
  <h2>{{ t('template.step.summary.label') }}</h2>
  <p class="hint-text">{{ t('template.step.summary.instruction') }}</p>
</template>
```

## Namespace Conventions

Follow these prefixes to keep the global namespace organized:

| Namespace    | Usage                                    | Example                       |
| ------------ | ---------------------------------------- | ----------------------------- |
| `app.*`      | Core UI, navigation, layouts             | `app.home.title`              |
| `common.*`   | Reusable UI labels (Save, Cancel, Close) | `common.actions.save`         |
| `errors.*`   | System-level error messages              | `errors.generic`              |
| `template.*` | Process template content                 | `template.step.summary.label` |

## Common Patterns

### Standard Actions

Use `common.actions.*` for consistency:

```vue
<button>{{ t('common.actions.save') }}</button>
<button>{{ t('common.actions.cancel') }}</button>
<button>{{ t('common.actions.delete') }}</button>
```

### Dynamic Messages

Use named interpolation for dynamic values:

**In JSON:**

```json
{
  "welcome": "Hello, {name}!"
}
```

**In component:**

```typescript
t('app.welcome', { name: userName.value })
```

### Form Fields

Provide both labels and placeholders for clarity:

```vue
<AppTextField
  :label="t('template.step.genre.label')"
  :placeholder="t('template.step.genre.placeholder')"
/>
```

## Testing with i18n

Always use the custom test renderer from [`@testHelpers/renderer`](../../src/__testHelpers__/renderer.ts):

```typescript
import { render } from '@testHelpers/renderer'
import MyComponent from './MyComponent.vue'

test('renders translated text', async () => {
  const { getByText } = await render(MyComponent)
  expect(getByText('Working Title')).toBeInTheDocument()
})
```

The custom renderer automatically injects a test i18n instance with both app and Snowflake template strings.

## Troubleshooting

### Missing Translation Keys

**Symptom:** UI shows raw key like `app.home.title`

**Solutions:**

1. Verify key exists in the correct locale file
2. Check spelling (case-sensitive)
3. Ensure template strings use `template.*` prefix
4. Restart dev server if you just added the key

### TypeScript Errors

**Symptom:** `t()` doesn't autocomplete or shows errors on valid keys

**Solution:** Update `MessageSchema` in [`src/i18n/types.ts`](../../src/i18n/types.ts) to match JSON structure

### Using i18n Outside Components

**Symptom:** `useI18n must be called in setup()`

**Solution:** Use the global instance:

```typescript
import { i18n } from '@/i18n'

function utilityFunction() {
  return i18n.global.t('common.actions.save')
}
```

### Tests Failing with Missing Keys

**Symptom:** Tests can't resolve translation keys

**Solution:** Use custom `render` from [`@testHelpers/renderer`](../../src/__testHelpers__/renderer.ts), not the base vitest-browser-vue one

## Validation Checklist

Before committing i18n changes:

- [ ] Added key to appropriate locale file
- [ ] Updated TypeScript schema (for static strings)
- [ ] Used correct namespace (`app.*`, `common.*`, `errors.*`, or `template.*`)
- [ ] Tested in component with `useI18n`
- [ ] Verified tests pass
